# Frontend Integration Guide: Real-Time Notifications

This guide explains how to connect the frontend application to the new real-time WebSocket notification system in RecruitOS. The backend uses Django Channels to instantly push notification events to connected clients.

## 1. WebSocket Endpoint

The backend provides a secure WebSocket endpoint that requires an active user access token.

- **URL Format:** `wss://<API_DOMAIN>/ws/notifications/?token=<ACCESS_TOKEN>`
- **Example:** `wss://0tc80btl-8000.inc1.devtunnels.ms/ws/notifications/?token=eyJhbGci...`

> [!IMPORTANT]
> Because standard browser `WebSocket` APIs do not support setting custom `Authorization` headers, **the JWT access token must be passed as a query parameter (`?token=`)**.

## 2. JSON Message Format

When a new notification is generated by the system (e.g., CV upload, stage change, interview scheduled), the backend instantly broadcasts a JSON payload to the user's active WebSocket connection.

The incoming message will look like this:

```json
{
    "type": "notification.created",
    "notification": {
        "id": "2714aaa9-3cee-4707-97eb-4064c4419d16",
        "title": "Realtime Check",
        "message": "It works!",
        "type": "info",
        "name": null,
        "event": null,
        "process": null,
        "link": "",
        "created_at": "2026-08-19T11:53:50.132Z",
        "is_read": false
    }
}
```

## 3. Recommended Implementation (React)

For a stable experience, your WebSocket client should handle automatic reconnections (e.g., if the user's internet drops or the server restarts). You can use a library like `react-use-websocket` or write a custom hook.

Here is a standard implementation using a custom React Hook:

```javascript
import { useEffect, useState } from 'react';
import { toast } from 'react-toastify'; // Example toaster library

export const useNotifications = (accessToken) => {
    const [notifications, setNotifications] = useState([]);
    const [unreadCount, setUnreadCount] = useState(0);

    useEffect(() => {
        if (!accessToken) return;

        // 1. Establish Connection
        const WS_URL = `wss://api.yourdomain.com/ws/notifications/?token=${accessToken}`;
        const ws = new WebSocket(WS_URL);

        // 2. Handle Incoming Messages
        ws.onmessage = (event) => {
            const data = JSON.parse(event.data);
            
            if (data.type === 'notification.created') {
                const newNotification = data.notification;
                
                // Add to list and increment unread count
                setNotifications(prev => [newNotification, ...prev]);
                setUnreadCount(prev => prev + 1);

                // Show a toast popup to the user
                toast.info(`${newNotification.title}: ${newNotification.message}`, {
                    onClick: () => {
                        if (newNotification.link) {
                            window.location.href = newNotification.link;
                        }
                    }
                });
            }
        };

        // 3. Handle connection close/errors (add reconnect logic here if needed)
        ws.onclose = () => console.log("WebSocket Disconnected");
        ws.onerror = (err) => console.error("WebSocket Error: ", err);

        // Cleanup on unmount
        return () => {
            ws.close();
        };
    }, [accessToken]);

    return { notifications, unreadCount };
};
```

## 4. HTTP APIs (For Initial Load and Management)

While WebSockets handle *new* notifications in real-time, the frontend still needs standard HTTP APIs to fetch history and mark items as read.

### Fetch Notification History
Call this when the app loads to populate the initial notification bell dropdown.
- **GET** `/api/v1/notifications/`
- **Params:** `?unread=true` (optional, fetches only unread) or `?limit=10`
- **Header:** `Authorization: Bearer <TOKEN>`

### Mark Single/Multiple as Read
Call this when the user opens the notification dropdown or clicks a specific notification.
- **PATCH** `/api/v1/notifications/mark-read/`
- **Header:** `Authorization: Bearer <TOKEN>`
- **Body:**
  ```json
  {
      "ids": ["2714aaa9-3cee-...", "uuid-2"],
      "is_read": true
  }
  ```

### Mark All as Read
- **POST** `/api/v1/notifications/mark-all-read/`
- **Header:** `Authorization: Bearer <TOKEN>`

## 5. Security & Flow Considerations

> [!TIP]
> **Multiple Tabs:** The backend groups connections by User ID. If the user has 3 tabs open, all 3 tabs will receive the WebSocket event simultaneously. Make sure your React state management (like Redux or Zustand) handles cross-tab state syncing if necessary, or just rely on the API for ground-truth read status.

> [!WARNING]
> **Token Expiry:** If the access token expires while the WebSocket is connected, it will typically stay open until disconnected. If you refresh the token via your refresh API, you may want to close and reopen the WebSocket with the new access token to ensure it doesn't get rejected upon a silent reconnect attempt.
